Parte 1

Mezclar dos listas ordenadas

La pieza que no es recursiva. Todo lo demás se apoya en ella.

Dos montones de exámenes

El menor de todos está arriba de un montón

def mezclar(a, b):
    resultado = []
    i, j = 0, 0
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:
            resultado.append(a[i])
            i += 1
        else:
            resultado.append(b[j])
            j += 1
    resultado.extend(a[i:])
    resultado.extend(b[j:])
    return resultado

Debajo del de arriba, todos son mayores. Por eso basta comparar los dos de arriba. Cuando un montón se acaba, el otro va entero al final.

de ade blos dos de arriba
Cuánto cuesta

Cada elemento se mira una vez

Las vueltas
Cada vuelta del while pone un elemento en resultado. Hay como mucho len(a) + len(b) vueltas.
Sin ciclo dentro de otro
La selección vuelve a recorrer lo que queda en cada vuelta. La mezcla coloca y no vuelve a tocar. Mezclar cuesta tanto como la cantidad de elementos.
El <=
Con dos iguales arriba, se toma primero el de a. Los iguales conservan su orden: es la estabilidad de la conferencia 8.

En la animación anterior, el escenario con iguales lo muestra: los 3 de a salen antes que el 3 de b.

def mezclar(a, b):
    resultado = []
    i, j = 0, 0                 # el de arriba de cada montón
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:
            resultado.append(a[i])
            i += 1
        else:
            resultado.append(b[j])
            j += 1
    resultado.extend(a[i:])     # lo que quede de a
    resultado.extend(b[j:])     # o lo que quede de b
    return resultado

Parte 2

Ordenación por mezcla

Si sabes mezclar, ordenar es partir a la mitad, ordenar cada mitad y mezclar.

La recursión de la conferencia 9

Ordenar cada mitad es el mismo problema

def ordenar_mezcla(lista):
    if len(lista) <= 1:
        return list(lista)
    medio = len(lista) // 2
    izquierda = ordenar_mezcla(lista[:medio])
    derecha = ordenar_mezcla(lista[medio:])
    return mezclar(izquierda, derecha)
  • Caso base: cero o un elemento ya están ordenados.
  • Devuelve una lista nueva, como sorted. Por eso list(lista): una copia, no la misma lista con dos nombres (conferencia 4).

La animación mezcla en el mismo lugar para que se vea; el código construye listas nuevas. Lo apagado está fuera de la llamada actual.

El árbol de llamadas

Bajando parte, subiendo mezcla

  • Bajando, cada llamada parte su lista a la mitad, hasta listas de un elemento.
  • Subiendo, cada nodo pasa a mostrar lo que devuelve: la mezcla de sus dos hijos.
  • A la derecha, cuántos elementos se mezclan en cada nivel.

¿Cuánto suma cada nivel?

Por qué es tan rápida

n por nivel, log₂ n niveles

Cada nivel mezcla n
Arriba, dos listas de 4 en una de 8. Abajo, cuatro mezclas de listas de 1. Los pedazos se achican, pero hay más: la suma es siempre la lista entera.
Hay log₂ n niveles
¿Cuántas veces se parte n a la mitad hasta llegar a 1? La pregunta de la búsqueda binaria: log₂ n. Con 8, tres niveles de mezclas.

Total: n log₂ n. Con un millón, n por 20, no n por un millón.

Comparaciones contadas en mezclar, con listas al azar. La mezcla hace algo menos que n log₂ n porque, cuando un montón se acaba, el otro se copia sin comparar.

Parte 3

Trabajar al partir

La ordenación rápida reparte la lista alrededor de un pivote, y así combinar no cuesta nada.

Ordenación rápida

Menores, iguales, mayores, y pegar

def ordenar_rapida(lista):
    if len(lista) <= 1:
        return list(lista)
    pivote = lista[0]
    menores, iguales, mayores = [], [], []
    for x in lista:
        if x < pivote:
            menores.append(x)
        elif x == pivote:
            iguales.append(x)
        else:
            mayores.append(x)
    return (ordenar_rapida(menores) + iguales
            + ordenar_rapida(mayores))
  • Todos los menores van antes que los iguales, que van antes que los mayores: pegar con + ya da la lista ordenada.
  • iguales nunca está vacía: tiene al pivote. Por eso las dos llamadas reciben listas más pequeñas.
pivoteel que se reparteya en su lugar
El árbol de la rápida

El árbol depende de dónde cae el pivote

  • La mezcla parte siempre a la mitad. La rápida parte donde caiga el pivote: el 38 deja cinco a la izquierda y dos a la derecha.
  • El pivote no baja: se queda en iguales. No se dibujan las llamadas con la lista vacía.
  • A la derecha, cuántos elementos se reparten en cada nivel.

La sorpresa

Más comparaciones, menos segundos

El mismo millón del libro, contado aparte. En la rápida cuentan el < y el ==.

# la mezcla: una vuelta por elemento colocado
while i < len(a) and j < len(b):
    if a[i] <= b[j]:
        resultado.append(a[i])
        i += 1

# la rápida: una vuelta por elemento repartido
for x in lista:
    if x < pivote:
        menores.append(x)

Contar comparaciones da el orden de crecimiento. El tiempo es ese orden por una constante: lo que cuesta cada vuelta. La de la mezcla calcula dos len, lee por índice y suma; la de la rápida recibe x y agrega.

Con el mismo orden, n log n, la constante decide.

¿Y sorted?

sorted es una mezcla escrita en C

Escrita en C
No en Python. Eso le da una constante mucho menor: el mismo trabajo, cada paso más barato.
Timsort
Es una ordenación por mezcla con mejoras: aprovecha los pedazos que ya vienen ordenados en la entrada.
Inserción abajo
Para los pedazos pequeños usa la inserción de la conferencia 8, que ahí es más rápida que seguir con la recursión.

Si la rápida es más rápida, ¿por qué sorted es una mezcla? Porque la documentación de Python promete que es estable: los iguales conservan su orden, y eso la rápida no lo da.

En la práctica

Los lenguajes usan las dos

DóndeQué usaPor qué
sorted, list.sort (Python)Timsort, una mezclapromete estabilidad
Arrays.sort de objetos (Java)Timsort, una mezclalos objetos iguales se distinguen: hace falta estabilidad
Arrays.sort de números (Java)rápida con dos pivotesdos números iguales son indistinguibles: la estabilidad no importa
std::sort (C++)introsort: rápida, que cambia de método si la recursión se hace muy hondavelocidad, y un peor caso n log n sin depender del azar
std::stable_sort (C++)una mezclalo dice el nombre

La regla: mezcla cuando hace falta estabilidad o un peor caso garantizado; rápida cuando no, por velocidad y memoria.

La rápida de verdad no crea listas

def particion(lista):
    pivote = lista[-1]
    k = 0                   # lista[:k]: los menores
    for j in range(len(lista) - 1):
        if lista[j] < pivote:
            lista[k], lista[j] = lista[j], lista[k]
            k += 1
    lista[k], lista[-1] = lista[-1], lista[k]
    return k
  • Nuestra rápida crea tres listas en cada llamada. Las de las bibliotecas intercambian dentro de la misma lista.
  • La mezcla necesita una lista auxiliar del tamaño de lo que mezcla. Esta rápida, ninguna.

Resumen

Lo que te llevas de hoy

  • Divide y vencerás: dividir en subproblemas más pequeños del mismo tipo, resolverlos recursivamente, combinar sus soluciones.
  • Mezclar dos listas ordenadas cuesta tanto como la cantidad de elementos: cada uno se mira una vez.
  • La ordenación por mezcla parte sin mirar y trabaja al combinar: log₂ n niveles con n de trabajo cada uno, n log₂ n. Es estable.
  • La ordenación rápida trabaja al partir, en menores, iguales y mayores que un pivote, y combinar es pegar.
  • Con el primero como pivote, una lista ordenada deja el árbol como una fila: cuadrática y RecursionError. Con el pivote al azar, n log n esperado con cualquier entrada.
  • Contar comparaciones da el orden, no el tiempo: la rápida compara casi el doble y tarda menos. Con el mismo orden, la constante decide. La mezcla es estable; la rápida, más rápida en la práctica.
  • El costo de un algoritmo recursivo se cuenta en su árbol: cuántos niveles y cuánto trabajo en cada uno. La binaria es divide y vencerás con un solo subproblema.
