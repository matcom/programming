Buscar, ordenar y contar lo que cuesta

Python ya trae in, index, sort y sorted, y en un programa de verdad se usan esos. Los escribimos a mano por la misma razón que sum y max en la conferencia 4: para saber qué hacen por dentro.

Parte 1

Búsqueda lineal

Mirar los elementos de uno en uno, hasta encontrarlo o hasta que se acaben.

Paso a paso

El primer índice donde está, o -1

def buscar(lista, x):
    """Devuelve el primer índice donde está x, o -1 si no está."""
    for i in range(len(lista)):
        if lista[i] == x:
            return i
    return -1
edades = [19, 18, 21, 18, 20, 22]
print(buscar(edades, 21))
print(buscar(edades, 18))

El return dentro del ciclo termina la función, y el ciclo con ella. Al return -1 solo se llega si el ciclo se acaba sin encontrarlo. El 18 está dos veces: devuelve el primero.

En vivo · archivo busqueda.py

Contar las comparaciones

def buscar_contando(lista, x):
    """Como buscar, pero devuelve también cuántas comparaciones hizo."""
    comparaciones = 0
    for i in range(len(lista)):
        comparaciones += 1
        if lista[i] == x:
            return i, comparaciones
    return -1, comparaciones

Parte 2

Búsqueda binaria

El juego de la conferencia 2: adivinar un número del 1 al 100 en siete preguntas, partiendo siempre el rango a la mitad. Ahora sobre una lista ordenada.

Paso a paso

Mirar el medio y descartar una mitad

def buscar_binaria(lista, x):
    """Busca x en una lista ordenada. Devuelve su índice, o -1."""
    izq = 0
    der = len(lista) - 1

    while izq <= der:
        medio = (izq + der) // 2
        if lista[medio] == x:
            return medio
        elif lista[medio] < x:
            izq = medio + 1      # x, si está, está a la derecha de medio
        else:
            der = medio - 1      # x, si está, está a la izquierda de medio

    return -1

izq y der marcan el pedazo donde el valor todavía puede estar. Si el medio es menor que x, todo lo que está a su izquierda también lo es.

Con el 12, que no está, los índices se cruzan: izq queda a la derecha de der, el pedazo queda vacío y el while se acaba.

Cuánto cuesta

Cada vuelta parte el pedazo a la mitad

for n in [1_000, 1_000_000, 1_000_000_000]:
    vueltas = buscar_binaria_contando(range(n), -5)[1]
    print(f"{n:>13}: {vueltas} vueltas")
         1000: 9 vueltas
      1000000: 19 vueltas
   1000000000: 29 vueltas
  • Las veces que hay que partir n a la mitad hasta llegar a 1 es log₂ n: log₂ 1024 = 10, log₂ 1 048 576 = 20.
  • Multiplicar la lista por mil le suma diez vueltas, porque 2¹⁰ = 1024.
  • range(n) se indexa como una lista ordenada y no ocupa memoria.

¿Por qué 9 y no 10? Si quitas el medio de 1000 quedan 499 a la izquierda y 500 a la derecha, y buscando un valor menor que todos la búsqueda siempre se va al pedazo chico.

El precio

Con una lista desordenada miente sin avisar

print(buscar_binaria([7, 2, 19, 5, 13], 5))
-1
Sin ningún error
El 5 está en la posición 3. La función mira el 19 del medio, que es mayor, y descarta toda la derecha, donde estaba el 5.

Descartar una mitad solo es correcto si la lista está ordenada. Si no lo está, la función hace lo mismo, pero el resultado ya no significa nada.

Un error plantado

izq = medio parece inofensivo

def buscar_binaria_mal(lista, x):
    izq, der = 0, len(lista) - 1
    while izq <= der:
        medio = (izq + der) // 2
        if lista[medio] == x:
            return medio
        elif lista[medio] < x:
            izq = medio          # antes era medio + 1
        else:
            der = medio - 1
    return -1

El medio ya se miró: ¿qué más da dejarlo dentro? Con pares = [0, 2, …, 18] y los 22 valores del −1 al 20:

14 de 22 búsquedas colgadas: [1, 3, 5, 6, 7, 9, 10, 11, 13, 15, 17, 18, 19, 20]

Cuando el pedazo tiene uno o dos elementos, el medio es el propio izq, e izq = medio no lo mueve. Lo que garantiza que un while termina es que cada vuelta achique algo. Prueba siempre con listas de 0, 1 y 2 elementos, y con valores menores que todos, mayores que todos y en medio.

Parte 3

Tres maneras de ordenar

Si buscar en una lista ordenada es tanto más barato, vale la pena saber ordenar. Sin sort ni sorted, y dentro de la misma lista.

Selección

Buscar el menor y ponerlo en su sitio

def seleccion(lista):
    """Ordena la lista de menor a mayor, modificándola."""
    n = len(lista)
    for i in range(n - 1):
        menor = i
        for j in range(i + 1, n):
            if lista[j] < lista[menor]:
                menor = j
        lista[i], lista[menor] = lista[menor], lista[i]

El intercambio es el desempaquetado de tuplas de la conferencia 4. La función no devuelve nada: modifica la lista que recibió, igual que sort.

Azul: definitivo, no se vuelve a mover. Naranja: la comparación. Rosa: el intercambio de la pasada.

Contar la selección

Siempre n(n − 1)/2 comparaciones

  • La primera pasada compara con los otros n − 1, la segunda con n − 2, la última con 1.
  • (n − 1) + (n − 2) + … + 1 = n(n − 1)/2. Con 7 elementos, 21.
  • No depende de cómo venga la lista. Aunque ya esté ordenada, para saber que el primero es el menor hay que compararlo con todos.
  • Con 1000 elementos, 499 500: casi medio millón.

El ciclo de fuera llega hasta n - 2: cuando los n - 1 menores están en su sitio, el último ya está en el suyo.

Inserción

Como se ordenan las cartas en la mano

def insercion(lista):
    """Ordena la lista de menor a mayor, modificándola."""
    for i in range(1, len(lista)):
        x = lista[i]
        j = i - 1
        while j >= 0 and lista[j] > x:
            lista[j + 1] = lista[j]  # corre el mayor
            j -= 1
        lista[j + 1] = x             # x cae en el hueco

Cada carta nueva se mete en su lugar entre las que ya tienes. El azul está ordenado entre sí, pero no son todavía los menores: lo que llegue después puede meterse en medio.

Violeta: x, levantada mientras busca su hueco. Rosa: el mayor que se corrió a la derecha.

Si la primera es falsa, la segunda no se mira

def insercion_contando(lista):
    """Ordena la lista y devuelve cuántas comparaciones hizo."""
    comparaciones = 0
    for i in range(1, len(lista)):
        x = lista[i]
        j = i - 1
        while j >= 0:
            comparaciones += 1
            if lista[j] <= x:
                break
            lista[j + 1] = lista[j]
            j -= 1
        lista[j + 1] = x
    return comparaciones

Burbuja

Intercambiar vecinos que están al revés

def burbuja(lista):
    """Ordena la lista de menor a mayor, modificándola."""
    n = len(lista)
    for k in range(n - 1):
        hubo_cambio = False
        for j in range(n - 1 - k):
            if lista[j] > lista[j + 1]:
                lista[j], lista[j + 1] = lista[j + 1], lista[j]
                hubo_cambio = True
        if not hubo_cambio:
            break

Al final de cada pasada el mayor de lo que falta llegó al final, como una burbuja. Por eso el ciclo de dentro llega cada vez un lugar menos lejos. Si una pasada no cambia nada, la lista ya está ordenada.

Prueba con la lista ordenada: una sola pasada de n - 1 comparaciones, y break.

def cronometrar(metodo, lista):
    """Segundos que tarda metodo en ordenar una copia de la lista."""
    copia = list(lista)
    inicio = time.perf_counter()
    metodo(copia)
    return time.perf_counter() - inicio

def ordenar_por_frecuencia(parejas):
    """Ordena parejas (palabra, veces) de más a menos frecuente."""
    for i in range(1, len(parejas)):
        x = parejas[i]
        j = i - 1
        while j >= 0 and parejas[j][1] < x[1]:
            parejas[j + 1] = parejas[j]
            j -= 1
        parejas[j + 1] = x

Resumen

Lo que te llevas de hoy

  • La búsqueda lineal mira uno por uno. En el peor caso, todos: trabajo proporcional a n.
  • La búsqueda binaria descarta la mitad en cada vuelta: diecinueve o veinte vueltas para un millón. Necesita la lista ordenada, y si no lo está miente sin avisar.
  • izq = medio + 1 y der = medio - 1 achican el pedazo en cada vuelta. Con izq = medio, el ciclo no termina.
  • Selección: el menor de lo que falta a su lugar, siempre n(n − 1)/2. Inserción: cada uno en su hueco, rápida con listas casi ordenadas, estable. Burbuja: vecinos al revés, hasta una pasada sin cambios.
  • Los tres son de orden n²: duplicar la lista multiplica el trabajo por cuatro. Un millón de elementos, horas.
  • Contar operaciones dice cómo crece el trabajo sin depender de la máquina. El reloj lo confirma.
  • Todo algoritmo nuevo se prueba contra uno que se sabe correcto, con muchas entradas pequeñas al azar.
